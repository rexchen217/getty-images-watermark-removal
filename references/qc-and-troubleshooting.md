# 报告判读与故障排查

**本文档分两部分：上半部分 A 分支（条纹），下半部分 B 分支（矩形蒙版）。**
先确认走的是哪条分支再往下读 —— 两者的报告字段完全不通用。

判断依据：`remove_stripe_watermark.py` 返回 `no_watermark_detected` 而图上明明有水印
→ 说明水印不是周期条纹，转B 分支 `rect_overlay.py`。

**B 分支在跑 `rect_overlay.py` 之前，先跑一次 `inspect_watermark.py`**
（只读体检，见下文「先跑体检脚本」一节）。它的输出比 `rect_overlay` 的报告更早、
更直接地暴露两类问题：**整条主带被静默跳过**，和**框边界偏了几十像素**。

# A 分支：条纹水印（`remove_stripe_watermark.py`）

## 报告结构

一次成功的运行会输出一份 JSON 报告，字段分五组。

| 分组 | 关键字段 | 用途 |
|---|---|---|
| 顶层 | status、mode、evidence_label | 本次运行的结论与所处模式 |
| alignment | level、ncc、scale_x、scale_y、shift_target_px | 两图对齐质量与所用变换 |
| stripes | label、normal_angle_deg、period_px_target、harmonics、significance、fold_explained、amplitude、confidence | 检测到的水印特征 |
| removal | strength、guard、low_freq_anchor_weight、mean_abs_change_255 | 实际施加的处理强度 |
| qc | suppress_db、detail_retention、detail_energy_ratio、low_freq_delta_pct、verdict | 结果质量与判定 |

`status` 的取值：

| status | 退出码 | 含义 | 应该怎么做 |
|---|---|---|---|
| ok | 0 | 去除完成且质检通过 | 直接交付结果图 |
| review | 0 | 去除完成，但有指标未达标 | 交付结果图，同时把 warnings 一并说明 |
| no_watermark_detected | 4 | 未检出有效条状水印，已原样输出 | 不要伪造去除结果，核对输入或放宽搜索范围 |

## 指标怎么读

### suppress_db（条纹抑制比）

去除前后在条纹谐波频点上的能量比。参考量级：

| 取值范围 | 判读 |
|---|---|
| 大于 15 dB | 条纹基本清除干净 |
| 6 到 15 dB | 有明显改善，可能残留极淡的纹路 |
| 小于 6 dB | 抑制不足，报 review |

只有在横条纹和斜纹上用与检测一致的投影坐标系测量，这个数字才有意义。
如果看到 1 dB 以下甚至负数，先怀疑测量坐标系而不是算法本身。

### detail_retention（高频结构相关度）

去除前后高频分量的相关度，接近 1 表示真实细节被原样保留。
低于 0.97 说明去除动到了不该动的地方，通常是条纹方向与真实纹理方向重合。

### detail_energy_ratio（高频能量比）

| 取值范围 | 判读 |
|---|---|
| 低于 0.85 | 过减，纹理被削平了 |
| 0.85 到 1.15 | 正常 |
| 高于 1.15 | 过冲，可能引入了新的纹路 |

### low_freq_delta_pct（低频偏差）

结果与参考图极低频分量之间的相对偏差，用来发现整体色调或亮度漂移。
自参考模式下没有参考图，该项为 null，属于预期行为而不是故障。

### fold_explained（周期解释率）

折叠出的周期波形能解释残差投影方差的比例，是判断"这到底是不是条纹"最直接的指标。

- 达到 0.6 以上：结构非常确定。
- 0.3 到 0.6：成立，但建议对结果多做一次目视核对。
- 低于 0.30：判定为没有有效条状水印。

含量结构（边缘、色块）的画面在投影剖面上也会形成频谱峰，但它们的周期解释率很低，
这就是把它和真条纹区分开的关键。

## 按照 warning 排查

| warning | 含义 | 处理 |
|---|---|---|
| 条纹抑制比仅 N dB，可能存在条纹残留 | 抑制不足 | 换激进档 `--strength aggressive`，或降低 `--guard` 后重试 |
| 高频结构相关度偏低，检查是否误伤了真实纹理 | 去除动到了结构 | 换保守档 `--strength conservative`，或提高 `--guard` 到 0.5 以上 |
| 高频能量降至 N，存在过减迹象 | 削平了纹理 | 同上；若画面主体就是同方向规则纹理，接受少量残留更稳妥 |
| 高频能量升至 N，可能存在过冲 | 引入了新纹路 | 换保守档，或把 `--guard` 提高 |
| 参考图与目标图对齐度中等，已降低参考图引导权重 | NCC 落在 0.60 到 0.90 | 结果仍可用；若追求更高保真度，改用同源的干净低清图 |
| 参考图与目标图对齐度不足或内容不一致，已切换为自参考模式 | NCC 低于 0.60 | 补一张内容一致的干净参考图；否则接受自参考模式的局限 |
| 未提供参考图，使用目标图自身的周期性估计条纹 | 走了 `--no-reference` | 同上 |
| 条纹显著性偏低，结果置信度有限 | 显著度未达强显著度 | 目视核对结果后再决定是否采用 |

## 常见故障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 退出码 2，`reference_required` | 没传 `--reference` 也没加 `--no-reference` | 补上参考图，或显式声明没有参考图 |
| 退出码 2，`output_conflict` | 结果路径与目标图相同 | 用 `--output` 指定别的路径 |
| 退出码 2，`output_exists` | 输出文件已存在 | 确认后加 `--force`，避免误覆盖 |
| 退出码 2，`target_too_large` | 目标图像素数超过上限 | 先降采样，或用 `--max-megapixels` 提高上限 |
| 退出码 2，`reference_missing` | 参考图路径不存在 | 核对路径；路径含空格时加引号 |
| 退出码 3，`missing_dependency` | Pillow 或 numpy 未安装 | 按 references/setup-guide.md 安装后重跑 |
| 退出码 4，`no_watermark_detected` | 没有可检出的条状水印 | 核对是否是条状水印；确认真有则收窄 `--min-period`、`--max-period` |
| 条纹方向判错 | 画面里有更强的主导纹理 | 用 `--angle` 直接指定方向后重试 |
| 周期报成真值的两倍或一半 | 谐波与次谐波在当前画面下等价 | 一般不影响去除效果，因为模板在整数倍周期下等价 |
| 结果出现整体偏色或偏亮 | 低频锚定不足 | 补一张同源低清干净参考图，让锚定权重回到 1.0 |
| 处理很慢 | 目标图分辨率过高 | 用 `--max-megapixels` 限制，或预先降采样 |
| 处理干净但文字边缘变糊 | 结构保护强度不够 | 提高 `--guard`，或换保守档 |

## 结果核对清单

A 分支交付前建议逐项过一遍：

1. 报告的 `stripes.label` 与用户描述的条纹方向是否一致。
2. `qc.verdict` 是否为 pass，若不是，warnings 里的每一条是否已解释清楚。
3. `mode` 是否为 `reference-guided`；若是 `self-reference`，向用户说明这一降级及其风险。
4. 目视核对条纹是否消失、主体纹理是否完整、文字与边缘是否清晰。
5. 结果图尺寸是否与目标图一致。
6. 退出码为 4 时，确认交付的就是原图，不要声称做过去除。

## 先跑体检脚本（`inspect_watermark.py`）

```
python scripts/inspect_watermark.py --reference <612干净图> --target <2048带水印图> \
    [--clean <已有结果图.png>] [--window y0,y1,x0,x1] [--json out.json]
```

只读，不改图。输出的每一段对应一个判读动作：

逐项怎么读：

| 输出 | 含义 | 不合格时怎么办 |
|---|---|---|
| `目标图 …  2048x1191` | 目标图**真实**像素尺寸 | 与文件名不符是常态，框坐标按这个尺寸写 |
| `配准 NCC=` | 参考图与目标图的对齐质量 | < 0.90 时残差含对齐误差，投影阶跃会变钝 → 核对参考图是否同源，或加 `--no-align-cache` |
| `α块扫描 …（N 个候选，α峰值 x）` | 主定位器的结果；α 峰值是块扫描里的最大值 | 峰值 > 1 通常是纯色底图上的徽标，不是错误 |
| `贴边条带 N 段` | 第三条定位器（贴边 64px 条带）找到的徽标候选数 | 为 0 且你确信图上有角落徽标 → 裁图确认徽标是否真的贴角（离角 >32px 会被排除） |
| `[i] kind box=…` | `bar`=可交给 rect_overlay；`badge`=角落徽标；`mismatch`=**纹理失配，别传 --box**；`weak`=不确定；`reject`=α>1 | 只把 `bar`/`badge` 的 `--box` 拿去执行 |
| `α=… (R²=…)` | 截尾回归的不透明度与拟合优度 | α 落 0.43–0.50 是 Getty 主带的正常值；**R² 两者都高，不能当判据** |
| `框内 med\|d\| vs 框外` | 框内外的残差量级 | 两者接近 = 没有稳定水印；差 5 倍以上才像水印 |
| `带符号稳健中心 内/外` | 条内外的带符号偏移 | **含白色图例文字或徽标时这一项会互相抵消，不要用它判断** |
| `参考图同区 lum std=` | 纯色底图判据 | < 1.5 时 α 回归必然失效，改走「参考图回填 + 框外羽化」 |
| `α 行/列阶跃` | 真蒙版应在 1–2px 内 α 从 ~0.05 跳到 ~0.45 | 是 0.10→0.20 的缓坡 = 条端本来就渐进（实测草地上确实如此），±10–20px 可接受；**看 α 台阶（0.012→0.47）比看绝对值可靠** |
| `行/列阶跃剖面` | 75 分位 \|d\| 从框外到框内的剖面 | 用来人工确认条的真实末端（徽标条两端常超出自动框） |
| `✗ 漏检：\|T-clean\| 中位仅 0.00/255` | **这块根本没被处理** | 这是自动检测静默跳过主带的硬证据，必须换框重跑 |
| `框内被改动像素占比 N%` | 结果图里框内被改动的像素比例 | 明显低于 100% = **框比真实水印宽**，那条边的 DC 是内容不是接缝 |
| `⇢ 框这条边多算了 xxx +Npx` | 真实合成边界在框内 Nbpx 处（小偏移） | 把该端收 N px 重跑；实测 6px 的偏差对应 3.00/255 的可见台阶 |
| `⇢ 有 xxx 边在框内很深处才发现被改动` | 大偏移，说明这块的框与真正被处理的区域不是同一条边（两框重叠） | 该边的数字以真正被处理的那个区域为准 |
| `接缝 最大超额台阶 x/255` | `\|step_clean\| − \|step_target\|`，> 2 才报接缝 | 报接缝时对照 `step_target`：target 小、clean 大才是我们引入的 |
| `--box y0,y1,x0,x1` | 可直接粘贴到 `rect_overlay.py` | 执行前仍要看上面的阶跃剖面核对条端 |

**`mismatch` 那一行是这套输出最有价值的部分。** 它把「草地上有一块区域残差很大」
和「那里真有一条半透明蒙版」区分开 —— 前者传进 `--box` 只会用低清参考图把草地糊掉。
判据是 α（0.005 vs 0.473），不是 `frac`（0.609 vs 0.918，两者都很大，分不开）。

## 报告结构

| 分组 | 关键字段 | 用途 |
|---|---|---|
| 顶层 | `status`、`mode`、`outside_watermark_untouched` | 本次运行的结论与区域外是否逐位未变 |
| alignment | `scale_x`、`scale_y`、`shift_target_px`、`ncc`、`cache` | 配准质量；`cache` 是 `hit` 还是 `miss` |
| regions[] | 见下| 每个被重建的矩形区域 |
| rejected_regions[] | `box`、`alpha`、`reason` | 被拒绝的候选区域（判定为非水印） |
| 汇总 | `hf_restore_ratio_texture`、`lf_consistency_mean` | 整体纹理恢复与低频一致性 |

`regions[]` 每个元素的字段：

| 字段 | 含义 | 正常取值 |
|---|---|---|
| `box` | `[y0, y1, x0, x1]`，y1/x1 不含端 | 与水印实际范围吻合 |
| `alpha` | 蒙版不透明度 | 0.3–0.8；**>1.0 是硬错误** |
| `overlay_255` | 蒙版颜色 | 图库水印通常是灰白色 |
| `strategy` | 重建策略 | 见下|
| `ideal_gain` | 理想增益 `1/(1-α)` | 供参照 |
| `gain_median` | 实际增益中位数 | 接近 `ideal_gain` 为好 |
| `noise_floor` | 噪声底估计 | Getty 实测 0.0035 |
| `region_hf` | 区域局部高频能量中位数 | 决定 `strategy` |
| `reference_fill_fraction` | 参考图回填像素占比 | **必须向用户交代** |
| `hf_restore_ratio_texture` | 纹理频段恢复比 | 理想 `1/(1-α)`，实测约 80% |
| `hf_restore_bands` | 分档恢复比明细 | 应当单调递减 |

`status` 只有两个取值：`ok`（至少有一个区域被重建）或`no_watermark_detected`
（没有找到任何合格区域，已原样输出）。

## strategy 怎么读

| strategy | 触发条件 | 含义 |
|---|---|---|
| `complementary-lf-hf` | `region_hf > 1.35 × noise_floor` | 正常蒙版，低频取参考图、高频按 `1/(1-α)` 恢复 |
| `reference-fill` | `region_hf <= 1.35 × noise_floor` | 底层内容在参考图里所剩无几，放大高频只会放大噪声，整框回填 |

`reference-fill` 不是失败，是正确决策 —— 角落 ID 徽标实测 96.5% 走这条路径，
因为低清参考图里那个位置本来就没有数字的细节。

## hf_restore_ratio_texture 偏低时怎么判断

实测 Getty 主带 1.649（理想 2.061，即 80%）。**这个缺口是设计代价，不是缺陷**：
自适应增益在局部高频接近噪声底时会把增益降到 1.0 以避免放大噪点。

**不要试图把它拉到理想值。** 要看分布就查 `hf_restore_bands`：

| 档 | Getty 主带实测 | 含义 |
|---|---|---|
| 0.000–0.008 | 1.776 | 近平坦区，增益受噪声底压制 |
| 0.008–0.030 | 1.649 | **真实纹理，主指标窗口** |
| 0.030–0.090 | 1.158 | 强纹理 + 文字边缘，混合 |
| 0.090+ | 0.805 | 白字 logo 及 JPEG 硬边振铃，走参考图回填 |

单调递减是**正常且正确**的。总比值明显低于 1 才说明重建真的失败。

## 按照 rejected_regions 排查

| reason | 含义 | 处理 |
|---|---|---|
| `alpha_out_of_range` | 回归出的 α > 1.0 或 < 0.05，物理上不可能，说明这不是半透明蒙版 | **已自动拒绝，该区域原样保留。必须向用户说明**：该区域被判定为非水印 |

真实案例：`897614882` 的一片草地被误检为水印区域，回归出 α=1.22。
若不拦，`alpha >= 0.80` 会触发 `reference-fill`，用低清参考图把草地糊掉 ——
一片真实的草变成模糊色块，比留着不动更糟。

## B 分支常见故障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 退出码 4，`no_watermark_detected` | 没有区域通过检测或 α 检验 | 确认水印是否存在；若存在，参考图可能与目标图内容不一致 |
| 某个区域 `alpha` 大于 1.0 | 该区域不是半透明蒙版（常见于草地、纯纹理、天空） | 已自动拒绝；若本该是水印，说明检测框偏了，检查配准是否正确 |
| 白字有残留| `alpha` 被回归得偏低，导致 gap 判据没触发 | 检查 `alignment.ncc`；ncc 低于 0.9 说明配准不可靠 |
| 出现**发光/发亮的字形鬼影** | 低频改用了 `(blur(T)-αC)/(1-α)` 反解值，白字能量泄漏进低频后被 `1/(1-α)` 放大 | 低频必须取参考图 `blur(A, σ)`。见 SKILL.md「B 分支的核心算法」 |
| 整条带子**糊掉**（不只是白字区） | logo 掩膜阈值定得太高/太低，误把大片普通纹理拉去参考图回填 | 掩膜应是「低阈值 + 膨胀 + 羽化」，实测 `gap>0.08` + 膨胀 8px + 羽化 14px |
| 白字区比周围更**锐/更糙** | 回填时对参考图做了 unsharp 补偿 | 不要锐化。`k·(A-blur(A,r))` 放大的正是放大插值痕迹，实测更糟（11.69→11.92/255） |
| 残留一道**极淡矩形轮廓** | 回填区用的是 612 参考图的低频，放大后有插值痕迹 | 属方法固有边界，无法完全消除；参考图分辨率越高越不明显 |
| 区域边缘有可见接缝 | 掩膜羽化溢出到框外 | `outside_watermark_untouched` 会是 `false`，这是 bug 需修 |
| 出现矩形色块 | 边界精修偏了几十像素 | 核对 `box` 与水印实际范围；差 1–2 像素属正常 |
| 文字区恢复成模糊色块 | 设计如此，白字下面是参考图回填 | 属预期，看 `reference_fill_fraction` 是否与预期相符 |
| `outside_watermark_untouched` 为 `false` | 掩膜溢出声明区域 | **是 bug 不是特性**，不要交付 |
| 配准结果明显错误 | 参考图与目标图内容不一致 | 换同源干净低清图；必要时加 `--no-align-cache` 排除缓存干扰 |
| 处理变慢且每次都慢 | 配准缓存始终 miss（键是「文件名+尺寸」组合，尺寸全变就会一直miss） | 正常，可接受；`<skill>/cache/` 可安全删除 |
| 同一批图反复出现相同 α 误判 | 误检区域与图库水印形状相似 | 逐张核对 `rejected_regions` |
| **报告 `status: ok`，但主带上水印一点没变** | 自动检测**整条静默跳过**了主带（不在 `regions`，也不在 `rejected_regions`） | 算整图 `|T-clean|`，恒为 0 的矩形区就是漏检区；用体检脚本的 `--box` 手动指定后重跑 |
| **草地/球衣织纹被当成水印处理掉** | 自动检测把「细纹理上采样失配」当成半透明蒙版 | α 回归能分开（真水印 0.43–0.50，失配 0.005–0.07）；先跑体检脚本，只把 `bar`/`badge` 的框传 `--box` |
| **角落徽标完全没动** | 徽标是「半透明底板 + 不透明白字」，α 回归给 0.000 或 >1，被当异常值拒了 | 徽标不能走 α 规则；看体检脚本的 `badge` 分类，以及 `ref_lum_std < 1.5` 时走「参考图回填 + 框外羽化」 |
| **体检报告里主带报了、徽标凭空不见** | 徽标的 `\|d\|` 只有主带的 0.14 倍（实测 18–20 vs 峰值 132.8），被全局相对阈值滤掉 | 已由「贴边条带相对基线」这一路覆盖；若仍为 0，看 `贴边条带 N 段`，并确认徽标是否贴角（离角 >32px 会被排除，此时用 `--window` 或手动 `--box`） |
| **数字条/logo 两端没去干净** | 徽标条两端超出自动框（实测左漏 31px、右漏 22px） | 用体检脚本的列阶跃剖面找条的真实终点，手动 `--box` |
| **徽标某一端留 5/255 左右的可辨台阶** | 框长边比标准徽标 192px 短 3~6px，少的几像素正是数字条末端残留（实测检测出 189） | `classify` 会提示「比标准徽标短 Npx」；把长边补到 192，实测右端 5.43 → +0.00/255 |
| **报告里出现两个几乎重合的框** | 去重跑在 `subsplit` 之前、用坐标容差，被 `subsplit` 收缩后的候选躲过判重 | 已修为「去重挪到 `subsplit` 之后 + 面积覆盖率 `≥0.85`」；实测 `1267196194` 的两个框 98% 重叠已消除 |
| **边缘有一道可见的亮/暗台阶** | 重建在框边留下了电平差 | 量超额台阶定位是哪条边；`step_target` 小、`step_clean` 大才是真接缝 |
| 边缘 DC 卡在 2/255 上下 | 外扩进来的干净像素被互补式重算了一遍 | **选精确框**，别外扩。实测某主带上边缘外扩到 1290 时 DC=2.09，收回到 1291 后降到 1.80 |
| **顶/底边（或左右边）有一条 3/255 左右的台阶** | 框这条边多算了几个像素（实测各多算 6px） | 工具会打出「框这条边多算了 top +6px」；把该端收 6px 重跑，实测 +3.00 → +0.00/255 |
| 工具的 `⇢ 有 xx 边在框内很深处才发现被改动` | 这块的框与真正被处理的区域不是同一条边（多为两框重叠，常见于 `mismatch` 块） | 该边的接缝数字以真正被处理的那个区域为准 |
| **α 荒谬（如 0.4594、overlay 是黄色）但目视结果干净** | 该框绝大多数像素走参考图回填，α 只作用于剩下的一小块 | **看 `reference_fill_fraction`**：实测 0.8316（83% 回填）时四边 DC ≤ 1.02，结果是对的。只看 α 会把正确结果判成失败 |
| 反锯齿的白字边缘留了 1–4px 的淡圈 | 硬边抗锯齿的过渡带 | **不要去修**。1:1 下不可见；提高阈值/加锐化/二次回填都会连真实纹理一起毁掉 |
| 竖幅图所有框都错位 | 文件名标 `2048x2048`、实际是 1279×2048 之类的尺寸不符 | 先读真实像素尺寸（体检脚本第一行就打），框坐标按真实尺寸写 |

## B 分支结果核对清单

交付前逐项过一遍，**不要只看 JSON 数字**：

1. `outside_watermark_untouched` 是否为 `true`。为 `false` 一定有 bug。
2. `alpha` 是否都落在 0.3–0.8；`rejected_regions` 是否有内容、内容是否合理。
3. `reference_fill_fraction` 的占比是多少 —— **必须主动向用户交代**哪些像素是回填而非真恢复。
4. 带体 1:1 裁剪：白色 logo/文字是否彻底消失，袖口罗纹、队徽、褶皱是否锐利。
5. **消融对照**：把「目标图 / 结果图 / 纯参考图」三张按同一裁剪框 1:1 竖排。
   这是唯一能区分「残留鬼影」和「参考图真实内容」的办法 —— 暗色织物褶皱
   往往是参考图的真实低频，不是残留。没有这一步很容易把正常内容当成鬼影，
   然后朝错误方向反复调参。
6. 徽标 1:1 裁剪：有没有数字、矩形边界或细暗线残留。
7. 四条边量**超额台阶**（`|step_clean| − |step_target|`），确认 ≤ 2/255。
   用体检脚本的 `--clean`，不要自己拿 clean 的台阶直接判 ——
   Getty 主带上下边的自然内容梯度本身就有 2–15/255（实测失配框左边有 9.01/255），
   超阈值要先看 `step_target` 是否同量级：同量级是内容，小得多才是我们引入的接缝。
8. 全图缩略图扫一眼，看有没有低频色块残留。
9. `alignment.cache` 是否为 `hit`；如果是 `miss` 且你觉得不该miss，加 `--no-align-cache` 复跑比对。
10. **每批都做一次残差热块扫描**：算整图 `|T - clean|`，确认没有矩形区恒为 0
    （恒为 0 = 那块根本没被处理）。`status: ok` 完全不能保证这一点。

**质检数字会骗人。** 实测教训：只统计 `gap>0.30` 的字芯时，白字区残差只有
+0.1/255，看着完美；但肉眼仍能看到明显鬼影 —— 因为鬼影在 `gap` 只有
0.05–0.30 的**羽化边缘带**。判据带必须覆盖膨胀后的完整影响区
（`gap>0.10` 再膨胀 4px），否则数字和肉眼会严重不一致。
