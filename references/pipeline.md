# 处理流程

**本文档分两部分：A 分支（条纹，第 1–4 节）与 B 分支（矩形蒙版，第 5 节起，
§5b 是 `inspect_watermark.py` 的体检与框标定算法）。**

# A 分支：条纹水印（`remove_stripe_watermark.py`）

整条链路分四段：配准、条纹辨识、去除、质检。所有分析都在一个统一的工作坐标系里完成，
避免反复旋转重采样带来的插值损失。

## 1. 配准

目的是把低分辨率无水印参考图放大并平移到与高清目标图对齐，让它成为可逐像素比较的低频真值。

1. 目标图按最长边缩到分析尺寸（默认上限 1600 像素），得到工作图。
2. 参考图先按工作图尺寸做各向异性缩放：沿 x、y 两个方向分别搜索尺度系数，用多尺度金字塔逐级细化。
3. 逐级做整数平移搜索，再在最优位置附近做亚像素精修。
4. 用重叠区域的归一化互相关（NCC）打分，作为对齐质量指标写入报告。

NCC 决定了后续走哪条路。因为水印是从残差（目标图减对齐后的参考图）里找的，
残差只有在两图真正对齐时才是纯粹的水印成分。

## 2. 条纹辨识

条纹是空间上的周期结构，辨识分四步。

### 方向

对残差做二维傅里叶变换，取有效频带内的幅度谱，按角度分箱统计每个角度的峰值与中位数之比。
条纹会在垂直于自身的方向上形成一条能量脊，脊的角度就是条纹法线方向。

自动估计给出显著度不足时，退化为直接比较 0 度和 90 度两个轴向。
当显著度足够高时，再固定周期扫描角度（先 0.5 度步长，再 0.1 度），取相位折叠能量最大的方向作为精修结果。

### 周期

沿投影坐标 `s = x·cosθ + y·sinθ` 把工作图分箱投影成一维剖面：

- `s` 是条纹的变化方向，`θ` 是条纹法线与 x 轴的夹角。
- 同一 `s` 上的像素取平均，随机噪声被平均掉，条纹被保留。

然后：

1. 减去三阶多项式趋势，去掉亮暗不均造成的低频起伏，同时不引入相位失真。
2. 对剖面做实数 FFT，在允许的周期区间内找显著峰，得到粗周期。
3. 在粗周期附近做两阶段相位折叠能量搜索（先 ±2%，再 ±0.1%），精修到亚像素精度。
4. 用倍率候选（1/8 到 8 倍）做谐波歧义消解，在能量平台上取最短周期。

折叠能量本身带有偏置：相位分箱数随周期线性增长，纯噪声下的组间方差期望约为 `(B-1)/N·var`，
直接用折叠方差会系统性偏爱大周期。因此实际使用的是**扣除该噪声基线后**的净能量，
这样不同周期的数值才可直接比较。

### 模板

按最终周期做相位折叠，把一维剖面重排成周期波形（去直流），得到条纹模板。
再用频谱筛选出模板的显著谐波索引，作为报告里的 `harmonics`。

### 铺场

把一维模板按投影坐标逐像素线性插值回二维，得到与工作图同尺寸的**模板场**。
这样斜向条纹也不需要旋转图像，天然没有旋转引入的锯齿和黑边。

## 3. 去除

条纹强度在整幅图上并不均匀，所以不能直接减模板，需要先估计每个位置的实际增益。

### 空间增益

1. 在滑动窗口内做最小二乘拟合：`G = Σ(R·P) / Σ(P² + ε)`，`R` 是残差，`P` 是模板场。
2. 滑动窗口用盒式滤波实现，与旋转、投影无关，因此在任意角度下等价。
3. 增益按窗口内的模板能量做置信度加权：模板能量弱的位置增益不可靠，向零收缩。
4. 全局增益与局部增益按档位加权混合，避免局部过拟合。
5. 亮度通道单独估一次增益，再与逐通道增益混合，减少色偏。
6. 对增益图做一次平滑，避免窗口边界出现条纹状接缝。

### 结构保护

真实纹理如果与条纹同方向，直接相减会造成过减。用结构张量判断：

- 计算梯度结构张量的相干性，相干性高说明该处是各向异性纹理而不是噪声。
- 比较纹理主方向与条纹法线方向，方向一致时降低该处的去除强度。

保护强度由档位决定：保守档保护最强，激进档保护最弱。

### 减法与回填

1. 从工作图减去 `增益 × 模板场`，得到工作坐标下的干净图。
2. 双三次重采样回目标图的原始分辨率。
3. 按对齐等级做低频锚定（见下节），修正色调亮度漂移。

## 4. 质检与判定

去除后重新测量，只有指标达标才判 pass。

- **条纹抑制比 `suppress_db`**：去除前后，在条纹谐波频点上的能量比，取对数。
  测量必须在与检测一致的投影坐标系上做，否则横条纹和斜纹的取样方向会把条纹平均掉，指标失效。
- **高频结构相关度 `detail_retention`**：去除前后的高频分量做重叠区归一化互相关。
  接近 1 表示真实细节原样保留。
- **高频能量比 `detail_energy_ratio`**：去除前后高频能量之比。
  明显低于 1 是过减迹象，明显高于 1 是过冲迹象。
- **低频偏差 `low_freq_delta_pct`**：结果与参考图的极低频分量之间的相对偏差，
  用来发现色调或亮度漂移。自参考模式下没有参考图可锚定，该项输出 null。

判定规则：抑制比达到 6 dB、结构相关度不低于 0.97、高频能量比落在 0.85 到 1.15 之间，三者同时满足才判 pass，
否则判 review 并在 warnings 里说明原因。

**为什么不把"无条纹"判成 pass**：如果图中本来没有条状水印，脚本会返回 `no_watermark_detected`
并以退出码 4 结束，原样输出目标图。这比硬做一次去除安全得多——后者会在干净图上凭空制造过减。

## 错位与内容不一致的分级处理

参考图和目标图不可能永远严丝合缝。按 NCC 分三级，各级的参考图权重不同。

| 级别 | 触发条件 | 处理方式 | 低频锚定权重 |
|---|---|---|---|
| L0 | NCC ≥ 0.90 | 参考图直接作为低频真值，全权重参与锚定 | 1.0 |
| L1 | 0.60 ≤ NCC < 0.90 | 参考图仍用于引导检测，但锚定权重折半，并在 warnings 中提示 | 0.5 |
| L2 | NCC < 0.60，或未提供参考图 | 放弃参考图，改用目标图自身的高频周期性估计条纹 | 0 |

各级的具体行为：

- **L0（轻微错位）**：亚像素平移与各向异性尺度已经吸收误差，残差基本就是水印。按常规流程处理。
- **L1（中等错位）**：残差里混入了对齐残差（边缘处的重影、纹理错位）。
  此时降低低频锚定权重，避免把参考图自身的重影当成真值灌回去；
  检测改用更严格的显著度与振幅门限，只在条纹明显时动手。
- **L2（内容不一致或无参考图）**：整个流程切换为自参考模式。
  - 先对目标图做高通预滤（截止频率取 `max(16, min(H,W)/12)`），把整幅亮度起伏压掉。
  - 周期搜索上限收紧到分析宽度的 1/10，避免把画面构图本身误当低频周期。
  - 显著度门限抬到 8.0、振幅门限抬到 0.008，只接受足够强的条纹。
  - 低频锚定为 0，不引入任何外部低频信息。
  - 报告中 `mode` 记为 `self-reference`，并给出切换原因的 warning。

自参考模式的固有局限：它无法区分"水印的周期"与"画面自身就有的规则纹理"。
因此当图像主体本身就是规则纹理时，应主动改用保守档或提高 `--guard`。

## 关键参数与档位

| 档位 | 增益缩放 | 窗口尺度 | 结构保护 | 全局收缩 | 适用场景 |
|---|---|---|---|---|---|
| conservative | 0.85 | 1.60 周期 | 0.45 | 0.45 | 细节优先，接受少量残留 |
| balanced | 1.00 | 1.15 周期 | 0.35 | 0.30 | 默认 |
| aggressive | 1.12 | 0.80 周期 | 0.18 | 0.15 | 残留明显，纹理简单 |

判定的门限常量：

| 常量 | 值 | 含义 |
|---|---|---|
| 最小显著度 | 4.0 | 峰高与中位数之比低于此值不认为是条纹 |
| 强显著度 | 8.0 | 达到此值才启动角度精修 |
| 最小振幅 | 0.004 | 条纹振幅下限（0 到 1 归一化尺度） |
| 最小周期解释率 | 0.30 | 折叠后周期波形能解释的剖面方差比例下限 |
| 峰值比 | 3.5 | 频谱峰值相对中位数的初筛倍数 |
| 对齐分级 | 0.90 / 0.60 | L0 与 L1 的 NCC 分界 |

# B 分支：矩形蒙版水印（`rect_overlay.py`）

## 0. 混合模型

水印是半透明蒙版叠加：

```
T = (1-α)·O + α·C
```

T= 带水印目标图，O = 原始内容，C = 蒙版色，α = 不透明度。
Getty 预览条实测 α ≈ 0.51，角落徽标 α ≈ 0.54。

对 `(T - A)` 关于 A 做迭代截尾最小二乘回归，`slope = -α`、`intercept = αC`，
一次同时解出 α 与 C。截尾是为了排除白字/logo 像素 —— 它们不属于这个混合模型。

## 1. 区域检测

1. 残差 `T - A` 做低通，行/列投影，各自按间断分组。
2. 行列都命中的交叉块才算候选区域，面积过小或形状过窄的丢弃。
3. `refine_box` 用 `walk()` 沿四个方向找真实的阶跃边界，把粗框收到水印实际外沿。
4. **α 越界即拒绝**：α 必须落在 [0,1]，越界说明这不是半透明蒙版
   （实测草地、精修木纹、天空会被误检），记入 `rejected_regions`，该区域原样保留。

## 2. 互补分解重建

```
O = blur(A, σ) + (T - blur(T, σ)) · gain_map        σ = 4.0
```

**必须用这个严格互补式。** 写成 `A + (T - blur(T,σ))·gain` 会让参考图在
0.05–0.15 cyc/px 频段与目标图高频重复计数，实测高频比冲到 2.4–2.7（理想 2.0），画面过锐。

σ = 4.0 的依据：参考图奈奎斯特约 0.15 cyc/px，σ 过小会让 0.03–0.12 cyc/px
区间用上参考图的软化版本，中部发糊。

**逐像素增益图**：

```
hfs = sqrt(box_mean(hf², 3))hf = (T - blur(T, σ)).mean(2)
k= sqrt(max(1 - (noise/hfs)², 0))
gain_map = clip(ideal · k, 1, 8)      ideal = 1/(1-α)
```

`hfs` 低于噪声底的位置把增益压到 1.0，避免放大 JPEG 噪点；
高于噪声底的位置朝 `1/(1-α)` 恢复。用标量增益会让画面发糊（实测 1.566 vs 理想 2.061）。

## 3. 白字/logo 与振铃

白字是**第二层不透明覆盖**，不属于混合模型。用「中性通道超出量」识别：

```
gap  = (T - P).min(2)                P = (1-α)·A + α·C
w_logo = blur(max_filter(clip((blur(gap,2.5) - 0.050)/0.045, 0, 1), 4), 2.0)
```

`min(2)` 是关键 —— 白字偏中性（三个通道都变亮），彩色纹理不会。

白字区走参考图回填 `A_fill = clip(A + 0.45·(A - blur(A,3)), 0, 1)`。
**字下面的内容在低清参考图里根本不存在，属按设计不可恢复**，
必须单独报出 `reference_fill_fraction`，不能假装恢复。

区域外沿另加振铃掩膜 `w_edge`，用**平台 + 锥形**而非线性锥形：

```
w_edge = clip(1 - max(dz - 3, 0)/6, 0, 1)
```

线性锥形会让硬边 JPEG 过冲在带体边缘产生 +0.02 的可见阶跃。

## 4. 局部化（性能关键）

`reconstruct` 只在「区域包围盒外扩 16px 的裁剪片」上运算，不是全图。

`LOCAL_MARGIN = 16` 的推导：3 次盒式滤波逼近高斯，σ=4 → radius=8 → 支撑约 24，留 4px 余量。
**实测 margin=16 时局部高斯与全图高斯在区域内 maxdiff = 0**。

裁剪片比全图快 13 倍（主带约 150×820 像素 vs 全图 2048×1475）。
QC 的高频图、低频一致性、logo 判据同样走裁剪片。

**掩膜尺寸陷阱**：掩膜要用裁剪片尺寸 `(cy1-cy0, cx1-cx0)`，
不是区域自身尺寸 `(ly1-ly0, lx1-lx0)`。区域只是裁剪片内部的一个子窗口，
用错会导致广播失败或静默错位。

## 5. B 分支的关键常量

| 常量 | 值 | 含义 |
|---|---|---|
| `SIG_SPLIT` | 4.0 | 低频/高频分界，也是 QC 统计用的高通 sigma |
| `LOCAL_MARGIN` | 16 | 区域裁剪的外扩边距 |
| `ALIGN_WORK_PX` | 256 | 配准 NCC 搜索的工作分辨率 |
| `HF_TEX_LO / HI` | 0.008 / 0.030 | 纹理频段统计窗口（针对 σ=4标定，勿乱改） |
| 噪声底分位数 | 8 | `noise_floor` 取局部 HF 能量的 8 分位 |
| α 拒绝阈值 | <0.05 或 >1.0 | 越界即判定为非水印 |
| `reference-fill` 判据 | `region_hf <= 1.35 × noise_floor` | 底层内容所剩无几时整框回填 |

## 5b. 体检与框标定（`inspect_watermark.py`）

只读工具，跑在 `rect_overlay.py` **之前**。它解决自动检测的两个已证实失效模式：
**整条主带被静默跳过**（不在 `regions` 也不在 `rejected_regions`，报告仍是 `ok`）、
**草地/球衣织纹被误检成水印**。

### α 面

```
Al = box_blur(A.mean(2), 4)
Sl = box_blur(T.mean(2), 4) − Al
```

先低通到 r=4 再回归，是这套判据能工作的前提：细纹理失配在高频上与 A 没有稳定
线性关系，低通把失配的高频能量压掉，只剩下「稳定偏移」这一项；
真实蒙版的低频关系 `Sl = −α·Al + αC` 不受影响。

回归用**截尾最小二乘**（8 轮、65 分位），与 `rect_overlay.fit_overlay` 同口径。

**平区守卫必须有**：`if u.std() < 0.012: return 0.0, 0.0`。
重度虚化的底图（草地、器材）在低通后方差极低，回归会给出 α = 3.4 / 9.4 / 6.39
这类荒谬值。没有这条守卫，这些区域会被当成"α 越界的水印"报出去。

**实测分离度**（9 组素材，故意挑难例）：

| 类别 | α | R² |
|---|---|---|
| 真主带 | 0.434 / 0.437 / 0.498 / 0.501 / 0.524 | 0.93–1.00 |
| 纹理失配 | 0.010 / 0.066 | 0.95–0.99 |

**R² 两者都高（截尾后必然高），不能拿 R² 当判据，只有 α 能分开。**

### 三条互补定位器

**① `locate_alpha`（主定位器）**：96px 块、hop 48、块内 stride=3，
逐块算 α；取 `0.15 ≤ α ≤ 1.0 且 frac ≥ 0.45` 的块做连通域，按 `MERGE_GAP=24`
合并、`MIN_BLOCKS=3` 过滤孤立块。
块边长 96 的取法：要明显大于纹理的相关长度、又小于最窄的水印条（主带高 147px）。
`stride=3` 是块内抽稀 —— α 面已做过全图 r=4 低通，抽稀不引入新错配。

**② `locate`（全局兜底）**：`|d|` 低通 r=6 → 16px 块均值 → 取**相对最强块**的
`REL_STRONG=0.35` 以上的块。用相对值而不是绝对值，因为不同素材水印强度差 3 倍以上。

**③ `locate_edge_badge`（贴边条带，专抓角落徽标）**：四条边各取 64px 深的条带，
沿边方向按 16px 块算均值剖面，与**条带自身的中位数**比：
`prof > max(3 × median(prof), 12/255)`。要求该段长度 48–640px、
且**贴到该边某一端 32px 以内**（角落徽标一定从角上长出来，6 组素材实测全部 x0=0）。

为什么必须单开一路：**徽标 |d| 只有主带的 0.14 倍**。实测 `2278372352`
徽标区 |d| 中位 18–20/255，而主带峰值 132.8/255 —— ② 的全局阈值
`0.35 × 132.8 = 46.5` 必然把它整块滤掉，表现为「报告只报出主带，徽标凭空消失」。
改用条带自身的基线后，该徽标被准确定位成 `[1134,1163,0,189]`（29×189，
与标准徽标 29×192 只差 3px）。

「贴角」这条不是拍脑袋：不加它，底边上任何 48–640px 的亮内容段都会被收进来 ——
实测 `1209892659` 会多出 x576–697 / x952–1072 两块底部内容（分类为 `mismatch`，
不进粘贴列表，但白占三行输出并稀释可读性）。

三条路的框位置差 ≤32px 视为同一个水印，合并去重；贴边候选额外用「与已有候选重叠
≥50% 就丢弃」避免重复报（`1203272712` 的徽标会被 ② 先找到，两条路的框一个含
2048 端、一个不含，互相包含的判据抓不住，必须用面积重叠）。

### α 投影边界精修

在主带这类弱纹理区，`refine_box` 的 `walk()` 常常找不到阶跃；徽标条又完全没有阶跃。
所以边界改用 **α 投影**来定：在框外 ±8px 的扫描带上逐条算 α，两遍（step=4 → step=1），
取**超过门限的扫描步的并集**。

三个细节都是踩出来的：

1. **取并集，不取中心连通段。** 用"与中心相连的那一段"会把 147px 的条切成 134×143。
2. **`hw` 只能是 8。** 用 32 时 ±32px 的扫描带把邻近内容一起平均掉，框会系统性高 20px。
3. **门限必须相对**：`min_alpha = max(0.15, 0.6 × a_in)`（`a_in` = 整框回归的 α）。
   条压在中间调内容上的一段 α 只有 0.15–0.20（实测 `2286834348` 的 x1064–1228），
   用固定 0.15 会把它当条的一部分，**整框向左虚扩约 160px**；
   相对门限下真实台阶（α 0.012 → 0.47）成为唯一的边界依据。
   每个扫描位置还要同时满足 `frac ≥ 0.45`，否则 α 的噪声会把框拉飞。

### 定性（`classify`）

判定顺序：`badge` → `reject` → `bar` → `weak` → `mismatch`。

| 类别 | 判据 |
|---|---|
| `badge` | `min(h,w) ≤ 80` 且 `frac ≥ 0.55` 且 `med_in ≥ 2 × med_out` 且贴图像边 |
| `reject` | α > 1.0 |
| `bar` | `α ≥ 0.15` 且 `frac ≥ 0.45` |
| `weak` | `0.08 ≤ α < 0.15` |
| `mismatch` | α < 0.08 —— 纹理失配，**不要传 --box** |

**徽标不能走 α 规则。** 它是「半透明底板 + 不透明白字」两层：白字要么把 slope
拉到 0（实测 α=0.000），要么在纯色底图上把回归推爆（实测 α=6.39）。
这两种结果都不代表"不是水印"，而恰恰对应 SKILL.md 里「纯色底图徽标 → 参考图回填」
那个已知行为。

**`badge` 的 `frac` 门限是 0.55，不是 0.85。** 徽标白字占框内的比例随底板明暗变化：
`1203272712` 的徽标压在中灰底上 `frac=0.639`，用 0.85 会被漏判成 `mismatch`，
用户于是被告知"不要传 --box" —— **徽标永远去不掉**。放宽后仍安全：7 组素材实测，
唯一被新捕获的正是那个真徽标；两个纹理失配框的 `min(h,w) ≥ 137`，本来就被
尺寸门挡掉，不靠 `frac` 区分。

**不要用带符号的条内外中心差。** 徽标里暗底板与白字互相抵消：实测带符号差只有
0.4/255，而 `med|d|` 是内 13.7 / 外 2.6。同理，**含白色图例文字的主带**也会因为
文字翻转中位数的符号而被误判成 `mismatch`（`2295161251` 实测 δ=5.6 被误判）。

**框长边比标准徽标 192px 短 3~6px 时，缺口那一端会留下 5/255 量级的接缝。**
Getty 标准徽标恒为 **29×192**，但 α 投影 / 贴边条带检测出的长边常短几个像素
（实测 `2278372352` 得 189）。少的这几像素正好是数字条的末端残留 —— 用这个框去跑，
右端接缝实测 **+5.43/255**，肉眼可辨。把框补到标准长度即可：

| 框 | 右端边界 | 右端超额台阶 |
|---|---|---|
| `--box 1134,1163,0,189` | col 188 | **+5.43/255（接缝）** |
| `--box 1134,1163,0,192` | col 191 | +0.00/255（干净） |

所以 `classify` 在 `badge` 分支里加了 `BADGE_STD_LONG=192` 提示：长边落在
`192-12 ≤ L ≤ 191` 区间时，直接把「比标准徽标短 Npx，先补足再看」写进结论，
免得用户拿着 189 的框反复调羽化。

**投影剖面用 75 分位，不用中位数。** 条只占窗口一部分时，中位数会被"条内一半是
干净内容"的窗口拉到干净侧；75 分位在条占窗口 ≥25% 时就落在条内。

### 接缝：在**实测边界**上量「超额台阶」

边界位置由残差自己定：从声明框的每条边向内最多 25% 的范围内，找第一条
「中位 `|T-clean| > 1/255`」的行/列，那就是真实的合成边界 —— 而不是假设它
就在框上。这同时解决了两件事：用户用的 `--box` 与体检框不同、以及框本身差几像素。
真实边界与声明框不一致时会给出 `boundary_shift`（小偏移提示「框这条边多算了 N px」，
大偏移提示「这块的框与真正被处理的区域不是同一条边」）。

```
excess = |step_clean| − |step_target|        阈值 2.0/255
step_* = 边界内侧 1 行/列均值 − 边界外侧紧邻 1 行/列均值
```

**不能直接拿 clean 自己的台阶判接缝**，四类实测情形：

| 情形 | step_target | step_clean | excess | 结论 |
|---|---|---|---|---|
| 该边未被改动（框偏宽） | 9.01 | 9.01 | 0.00 | 内容台阶，不是接缝 |
| 去掉水印自身的边（徽标底板） | +34.6 | 0.00 | 0.00 | **正确结果** |
| 重建留下电平差 | +2.19 | +6.59 | **+4.40** | **真接缝** |
| 重建贴合良好（主带四边） | −0.61 | −0.78 | +0.17 | 无接缝 |

第 1 行是最容易踩的坑：`2278372352` 的失配框左边本来就有 9.01/255 的自然台阶，
clean 也是 9.01，直接量就会报成"接缝风险"。第 2 行反过来：徽标底板那条边
target 有 +34.6/255，去掉水印后 clean 归零 —— 那是目标，不是缺陷。

**不要用「这条边有没有被改动」当门限。** 试过一个版本按「框内紧邻 4px 的
`|T-clean|` 中位 ≥1/255」判该边是否处理过：主带四条边虽然全被改动，
但靠近边界处的改动会自然衰减到 1/255 以下，于是四条边全被标成"不是合成边界"，
标签完全误导。`step_clean − step_target` 自带这个信息，不需要额外判据。

**行/列边各留 10% 的余量**（行边两端各裁 10% 列；列边上下各裁 10% 行），
避免把角点或条端之外的竖直内容边缘算进来。边缘取 1px 宽是刻意的 ——
接缝就是 1px 尺度上的不连续。

### 漏检扫描

`--clean` 的另一半用途：框内 `|T - clean|` 的中位若 < 1/255，说明**这块根本没被处理**。
这是「自动检测静默跳过主带」的唯一硬证据 —— 报告里 `status: ok` 完全看不出来。
同时报 `processed_fraction`（框内被改动像素占比），低于 0.85 提示**框比真实水印宽**。

### 已知失效模式

- **框精度 ±6px 是常态，必须靠接缝实测闭环收敛。** 实测 `2278372352`：α 投影给出的
  主带框是 `[712,877,…]`（165px 高），而真实条是 ~153px —— 上下各多算 6px。
  这个偏差在 α 剖面上看不出来（条端 α 从 0.003 升到 0.07 是渐进的），
  但用 `--box` 跑完再看接缝就一目了然：

  | 用的框 | 实测边界 | 顶边超额台阶 |
  |---|---|---|
  | `--box 712,877,…` | row 712 | **+3.00/255（接缝）** |
  | `--box 718,877,…` | row 718 | +0.00/255（干净） |

  所以**「体检 → 执行 → 复核 → 收 6px → 再复核」这个闭环不是可选项**，
  而是这套方法达到像素级干净的必要步骤。工具会把「框这条边多算了 top +6px」
  直接打出来，照着收即可。
- **`subsplit` 的 3×3 网格对「大片失配里嵌一条淡蒙版」常常无效**：
  `2278372352` 的 α 命中区比一个 3×3 单元还大，网格内部全都被失配稀释。
  好在 `locate_alpha` 会直接命中那条真蒙版，不依赖 `subsplit` 兜底。
- **去重必须放在 `subsplit` 之后，且用面积覆盖率而不是坐标容差。**
  实测 `1267196194`：一个 16×48 的小候选本来被判成 `mismatch`，`subsplit` 把它
  重标成 `bar` 并收缩/移动，最后落到整条主带上 —— 于是报告里出现两个
  `[840,999,1235,2048]` 与 `[846,993,1229,2048]`（**98% 重叠**）的近乎重复的框。
  根因是去重跑在 `subsplit` **之前**，用的是 6px 坐标容差，而这俩框正好差 6–7px，
  卡在容差边界上躲过了判重。修法两条一起上：① 把去重挪到 `subsplit` 之后；
  ② 判据从「坐标差 ≤6px」换成「任一方向的面积覆盖率 `_cover_ratio ≥ 0.85`」，
  双向都成立才算同一个水印。
- **`locate` 的 r=6 低通会把边界外扩约 8px**，所以它只用来「找极值」，
  定边界一律交给投影阶跃 / α 投影。
- **框比真实水印宽时，框边落在未处理区**，那条边的 DC 是纯内容。
  接缝实测已按「`|step_clean| − |step_target|`」自动排除这种情况，
  但仍会报 `processed_fraction` 提示框偏宽。

## 6. QC 统计口径

**高通 sigma 必须等于 `SIG_SPLIT`。** 用 σ=1.2 测而按 σ=4.0 重建，测的是另一个频段，
实测比值会从 1.65 掉到 0.28 —— 完全是伪影。

**必须排除参考图回填区。** 白字 logo 像素的 |高通| 可达 0.5，真实纹理只有 0.01 量级，
混在一起算 `std` 会被 logo 主导（主带比值掉到 0.17）。
所以 `reference_fill_fraction` 必须单独报出来。

顺带一提：只看「参考图局部平坦」（`|gA| < threshold`）来排除 logo 是**无效**的 ——
白字内部在参考图里也是平坦的，这个条件排不掉它们，反而会误采样。

命中时在缩略图上校验 NCC，低于记录值 0.03 就回落完整搜索。
一批图走 `--batch 清单.txt`，可摊掉逐张起进程约 0.3s 的导入开销。

**两条铁律，都是实测踩出来的：**

**1. `noise_floor` 必须全分辨率算** —— 试过按 `::2` 抽稀省 0.8s，但 `box_mean` 的邻域会被
抽稀成等效更小的窗口，噪声能量被系统性高估 **45%**（0.00351 → 0.00508），
连带把徽标区误判成错误策略。这 0.8s 不值得拿正确性换。

**2. `detect_regions` 也不能抽稀** —— 行/列投影统计里的 `int(w * 0.012)` 占比阈值、
`GAP_ROWS/COLS`、`min_area`、`<8`/`<20` 的尺寸门槛都不是按比例可缩放的量。实测 `::2`
会让 `145292342` 的区域从 4 个掉到 2 个、`672035684` 从 4 个掉到 2 个（漏检真实水印），
`::3` 还会凭空多出误检。

### 「降通道」不是「降分辨率」

真正安全的大头是**把三通道运算压成单通道**。盒式滤波是线性算子，
`mean(blur(T)) == blur(mean(T))`，凡是只需要 `T.mean(2)` 的地方都可以先把通道压掉，
浮点运算量与内存流量直接降到 1/3：

| 位置 | 原来 | 现在 | 2048×1365 实测 |
|---|---|---|---|
| `noise_floor` | `blur(T_rgb, 4).mean(2)` | `blur(T.mean(2), 4)` | 2082ms → 907ms |
| `detect_regions` | `blur((T-A).mean(2), 2.5)` | 已是单通道，不变 | — |
| QC 高频段 | `blur(Tl)` / `blur(Ol)`（本就是单通道） | 直接复用 `noise_floor` 算好的全图 σ=4 高频图 | 145ms → 45ms |
| QC 低频段 | `blur(O_rgb,10) - blur(A_rgb,10)).mean(2)` | `blur(O.mean2,10) - blur(A.mean2,10)` | 137ms → 49ms |
| `reconstruct` 的 `HF` | `blur(Ts_rgb, 4)` 算两遍 | 复用同一个 `blurTs` | 63ms/区域（大区域 0.5s+） |

`reconstruct` 里不能单通道化的只剩 `blurTs`（重建需要逐通道高频）和
`LF = blur(As, SIG_SPLIT)`（低频取参考图，需要彩色）。

### 噪声底为什么要量化到 6 位有效数字

`noise` 是标量，但它进了 `gain_map` 的 `k = sqrt(1 - (noise/hfs)²)` —— 在 `hfs ≈ noise`
附近这个式子对 `noise` 的扰动极其敏感。单通道化会让 `noise` 变化约 1e-6 相对量
（6 位有效数字之内），足以让个别恰好压在 1/255 量化边界的像素翻转 1 级。
把 `noise` 量化到 6 位有效数字后，输出对滤波实现的浮点末位差异免疫：
实测 9 组素材由「2 个像素差 1 级」收敛到 **输出 SHA1 完全相同**。
